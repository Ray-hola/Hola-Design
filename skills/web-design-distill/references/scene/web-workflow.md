# Website source paths

Use the existing extraction-pipeline.md when live Playwright page/CDP tools are
available. Set SKILL_ROOT to this folder (SKILL in the pipeline means the same
folder). Scripts are resources, not a one-command universal crawler.

Live pages: sample representative public pages inside the requested scope, inspect
actual tokens and components, then explain content/section purpose. Capture the
same relevant content at multiple widths for responsive claims. Do not publish,
submit a form or change an account merely to collect design evidence.

Source repository: find the rendered route and effective styling owner. Inspect
framework-specific theme declarations, used component variants and media queries.
Keep declared/used/computed values separate and preserve exceptions. Do not merge
near-duplicates merely because a single ideal palette is easier to describe.

Screenshots/images: inspect composition, text hierarchy and relative proportions.
Colors can be measured with available image tools, but exact font identity and
hidden state remain unknown. A picture of a mobile screen supports that screen's
appearance, not the breakpoint behavior of its desktop counterpart.

Existing extraction bundle: keep it as engineering evidence. To produce the
purpose-aware consumer, author the domain profile, list relevant snippets or images as
artifacts inside its folder, and use profile_tools.py. A bundle does not by itself
supply page purpose or responsive knowledge.

The generated profile package is application-neutral. Assets are inspected before
reuse; HTML from a source is untrusted reference material, not a script to execute.
Unavailable tools limit evidence. Preserve a useful draft instead of replacing
measurements with a stock design-system recommendation.

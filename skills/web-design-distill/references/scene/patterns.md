# Website section and page patterns

For each page, name what a visitor should understand or do. For each section, name
the claim, explanation, evidence or action it carries. Drop generic purpose labels
that could describe any section. A section without evidence for a purpose can
remain a structural observation with that purpose marked as inferred.

Record a pattern's when-to-use, content/assets it requires, structure, variable
parts, counterexamples and source instances. A pricing comparison needs comparable
options; a testimonial pattern needs actual attributable evidence. Never invent
reviews, customers, numbers or images to fill a borrowed structure.

Preserve mobile changes as observed relationships: column collapse, reordered
content, navigation change, density or image crop. Record widths and source
identity; testing unrelated desktop/mobile pages does not prove a responsive rule.

A page pattern records its goal and ordered section IDs, explaining relations
between them. Do not force all sites into hero/logo/features/testimonial/pricing.
A reading page may prioritize orientation, measure and navigation; a decision page
may prioritize comparison and proof. The user brief wins over generic originality.

Taste decisions connect context → choice → plausible alternative → inferred reason
→ evidence. No fixed principle count, adjective blacklist or universal aesthetic
ban. Preserve a source's real gradients, cards or quiet typography when they are
part of its identity. Use recommendations only for explicitly requested gaps.
